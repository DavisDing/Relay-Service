# DS 初始凭据审计复核与修复（2026-10-28）

核实对象为当前工作区源码，保留此前精简 Compose 的未提交工作。本轮未发布镜像、未触发远程 CI、未连接数据库或 NAS。

| 项目 | 核实结论 | 实际修复 |
|---|---|---|
| R1 中 | 成立：旧版长期 deployment.env 与原始文件均保留临时明文，cfg 也持有引用；原凭据在改密后已经失效，不是仍可登录的漏洞 | 包装脚本迁出临时字段，删除原始副本，长期配置仅含三键且归 root:65532/640。临时文件位于 Relay 所有的 initial/password，首次改密数据库提交后删除；失败仅告警并在已完成账号的重启中重试。启动准备后清空 cfg 引用和进程环境值；不声称能物理擦除 GC 旧副本、镜像环境配置或旧日志/备份 |
| R2 中 | 条件成立：原始密码未变时重启正常；失配才以 ErrInvalidInput 失败，不能概括为所有改密前重启失败 | 使用明确的缺失/不匹配错误，启动层降为脱敏告警；不打印错误密码，不重置数据库账号，原临时凭据和受限 API 规则不变。长期配置损坏/数据库错误仍拒绝启动 |
| R3 低 | 成立：登录页未认证可见部署凭据获取路径；提示本身不授予日志访问权限 | 移除登录页该句；部署者操作指引继续保留在文档与部署日志，页面结构和功能不变 |
| R4 低 | 成立：解析器强制四键齐全 | 允许白名单键子集，以环境覆盖文件后验证有效配置；继续拒绝重复、未知、空值及非法内容。临时密码/迁移连接缺省允许，数据库 URL 和加密密钥仍必需 |
| R5 低/测试夹具 | 成立：剩余不足一秒时可计算出负 lifetime，不影响生产 | 初始化前不足一秒提前跳过；定时器按剩余时间比例预留退出时间，拒绝非正剩余时间，正常上限仍八分钟 |

权限变化：Compose 的秘密卷改为可写，以删除一次性文件。卷根目录和 current 仍由 root 控制（755/710），长期配置及五个原始长期秘密不向 Relay 开放写权限；只有 initial 子目录归 UID65532（700），密码文件600。应用仍使用非 root UID65532。真实 Linux UID/卷权限与 Docker/NAS 行为尚未实测。旧四键配置需与新的数据库包装镜像一并更新，不能只更新应用镜像并声称旧明文已经清理。完全手工/只读挂载若无法删除旧文件，会告警，需要部署者修复权限后重试；不会伪报清理成功。

验证结果：

- `go test -race ./...` 通过，包括新增配置/账号生命周期/清理失败测试。
- 嵌入 Web 的 webui/api/cmd 竞态测试及 `go vet -tags webassets ./...` 通过。
- Web18项测试、TypeScript检查与生产构建通过；源码与构建资源不再包含旧部署路径提示。
- scripts27项和.github/scripts9项通过：覆盖首次生成、临时密码迁出、改密文件消费后重启不再生成、迁移中断重试、持久化秘密不变、打包等。
- fixture200ms超时实际提前跳过；3秒超时实际监听并正常关闭。首次受限执行因禁止回环端口绑定失败，获执行权限后同一测试通过。
- shell/YAML语法和git diff --check通过。Docker CLI/daemon不可用，真实数据库、容器、NAS及镜像发布未执行。

事务边界：先提交正式凭据、使临时会话失效，再删除文件；这两项不可能构成跨数据库/文件系统原子事务。删除失败通过告警和重启重试收敛，不能保证失败瞬间不存在已失效明文。部署日志与历史备份不自动擦除。
