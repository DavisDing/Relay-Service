### 0.3 端到端业务路径（已确认目标的整理；步骤细化 PROPOSED）

| 路径 | 预期顺序 | 不能被省略的失败反馈 |
|---|---|---|
| 既有网关接入 | 管理员登录 → 保存地址/服务端凭据 → 只读识别可得的版本/权限 → 执行无推理基础检查 → 按接口能力同步目录等增强数据 → 按需启用独立写操作/探针 | 版本/目录接口不可得时标明未知或受限；无权限、无数据库、接口不支持分别说明；首次接入不触发付费推理 |
| 管理变更 | Web 展示目标与当前状态 → 校验权限 → 高风险二次确认 → 调用网关 → 核对实际结果 → 审计 | 超时/部分成功显示待核对，不能重复创建或假装全部成功 |
| 探针与告警 | 管理员明确启用 → 冻结选模/测试版本 → 估算并预留预算 → 执行 → 归因/对账 → 存证/告警 → Mac/Android 同步 | 未测、预算暂停、证据不足、过期不显示为通过；系统限制后台时不承诺即时通知 |
| 新 Mac 安装/后续升级 | 空数据首装 → 可信配对 → API/schema 协商 → 读取 NAS 快照；后续升级前备份 → 版本迁移 → 读回/回归 → 继续服务 | 不要求旧 Relay 数据；升级失败不清空 NAS；不兼容拒绝写入并提示升级，缓存可重建、偏好需保护 |
| Android 连接与升级 | 输入 NAS 地址 → 处理适用的网络/通知权限 → 一次性配对 → 版本协商 → 快照/告警同步；升级核对签名和本地设置 | 拒绝权限、设备撤销、后台受限、离线与版本不兼容分别反馈；安装/更新渠道由设计冻结 |
| 统一服务与版本查看 | 配置 Relay 接入项/分组 → 无推理基础检查 → 按能力和权限展示状态及可得的模型/额度 → 打开原 WebUI；有可信运行镜像证据时比较更新 | 服务可达不代表模型可用；无运行 digest 时更新状态未知，转 UGOS 人工核对 |

步骤依赖不是授权：付费调用、线上配置写入、部署和删除仍按 13.5 单独明确范围。

## 1. 背景与产品目标

### 1.1 已确认方向（CONFIRMED）

- NAS Docker 中的 Relay 服务端采用 Go（D-15，CONFIRMED 2026-10-26）；具体工具链、依赖与镜像版本在实施前验证并锁定，不改变既有 LiteLLM 运行时。
- Mac、Android 客户端与 NAS 服务端/Web 同属本新项目；本项目业务数据从空数据初始化，保证本项目后续 NAS/客户端版本升级的数据兼容，细则见 FR-C04/C05/C06。
- 统一管理多个供应商、中转站及其不同模型，不假定所有渠道提供相同模型。
- 用户配置监控/统计/余额接入所需凭据；Relay 不要求具备对外调用 Key 的生成/分发/管理能力。实际推理客户端继续使用既有网关/服务的调用入口与 Key，见 D-14。
- 提供消费、用量、请求日志、服务探针和模型状态信息。
- 探针覆盖“是否可用”、能力支持和疑似质量回退（用户所称“降智”）。
- 能对接 NAS 已经通过 Docker Compose 部署的 LiteLLM，不要求重新部署或重建网关。
- 优先复用/参考 LiteLLM、Sub2API、CC Switch 等现有项目，不重复造轮子；必要时评估适配或最小修改。
- Mac 软件可以连接服务端；期望配置后自动连接、重连并更新数据。
- Android 17 / Xiaomi 15 提供连接 NAS Relay 的只读监控与告警客户端，复用服务端配对/撤销和版本合同；通知与后台同步遵循 Android 平台能力。
- NAS Relay Web 提供统一服务管理与运维入口，汇总 Relay、LiteLLM、Hermes、workbuddy2api、Open WebUI、Ollama、MetaCubeXD 的状态、分组模型状态、可得额度/余额和原 WebUI 链接；同时提供任务/告警、日志诊断、备份恢复指引、版本/审计/系统设置等工作区，详见 FR-W02。
- 固定连接关系：Mac/Android Relay → NAS Relay 服务端 → LiteLLM；设备客户端不直接管理 LiteLLM 或上游。
- 首期核心为现有服务运维监控、Relay 管理 Web、模型/渠道信息、受控可用性/能力/质量探针和告警；不以 Relay 提供调用 Key 为前提。原 LiteLLM 模型/路由写管理按 FR-M02 单独验证，不阻塞其他服务监控。
- 首期支持 API Key 接入；订阅/OAuth 账户池不纳入首期。
- 当前数据/管理主线为 LiteLLM、workbuddy2api 和 Pipio/DeepSeek 等供应商余额；workbuddy2api 独立能力按 D-03 冻结。Ollama 仅纳入 FR-W02 无推理总览，统计/模型管理/主动探针暂缓；保留 Open WebUI 现有直连路径，不修改 Ollama 服务。支持多实例配置，首个验收以现有 NAS 为准。
- 管理和全局配置集中在 NAS Web；Mac 保留设备连接、展示和通知等本地配置。
- 质量异常只告警，不自动更改路由或下线模型；首期 Web 留存全部告警，Mac 在线且获得系统许可时发送本机通知，邮件/Webhook 不纳入首期。
- 项目交付可通过明确端口访问的 Web/API；用户自行配置 Lucky 等反代实现远程 HTTPS，不交付 Lucky 配置管理，不以提供其域名/证书/规则作为需求前提。
- Mac 目标系统为 macOS 27，不保留独立本地直连模式，需要自动更新。
- 现有能力按需要复用，必要时重构；具体变更需有范围与回归验证。

### 1.2 成功标准（PROPOSED）

用户保留现有 LiteLLM，完成一次接入后，能够：

1. 查看当前可访问模型与渠道，不混淆对外别名和实际上游部署。
2. 查看请求用量、计算费用、可用性和最近数据时间。
3. 运维监控覆盖六个现有服务，按可得证据区分自然流量与探针；无需由 Relay 创建或分发调用 Key。
4. 按受控预算进行能力和质量检测，获得附证据的结果。
5. 在 Mac 菜单栏/详情与 Android 状态/告警页读取一致的数据；后台限制与最后同步时间明确可见。
6. 数据库、网络或上游异常时看到明确错误与旧数据时间，而非伪造成功或零消费。

### 1.3 非目标

- 不在首期重写完整 LiteLLM 或建立第二套并行扣费、Key 和预算引擎。
- 不把平台变成公开售卖额度、充值、支付、代理商结算系统。
- 不承诺仅凭探针证明底层模型身份或确认供应商“换模型”。
- NAS 支持按明确配置保存请求/回答正文，默认关闭，开启后默认保留 7 天且可配置；不自动扩大到 Cookie、订阅会话或所有附件。
- 不默认接管 NAS 容器、升级现有服务或改变现有调用路由；本项目初次安装不依赖旧 Relay 数据，后续版本升级必须通过版本化 schema、API、快照和兼容窗口保护 NAS 与 Mac 数据。
- 不将自动发现视为可信授权，不自动向发现的服务器发送凭据。
- 不默认建设微服务、Kubernetes、集中日志集群或大规模评测集群。

## 4. 领域对象与模型支持

### FR-M01：模型目录（CONFIRMED）

## 5. Key、权限与秘密边界

### FR-K01：凭据隔离（CONFIRMED 目标）

至少区分：

1. 上游模型调用凭据。
2. 上游余额/账单管理凭据。
3. LiteLLM 管理/集成凭据。
4. 客户端模型调用 Key。
5. 探针调用 Key。
6. Relay Mac/Android 各自独立的设备凭据。
7. Relay 管理员认证。

模型调用 Key 不代表拥有管理接口或账单读取权限；Mac/Android 监控凭据不代表模型调用权限。统一服务只读检查凭据按服务/用途隔离，不复用设备凭据。

### FR-K02：调用 Key 能力边界（不列必需交付；D-14 CONFIRMED 2026-10-26）

- Relay-Service 可以不具备面向客户端的调用 Key 创建、签发、分发、轮换、撤销、预算/有效期编辑或推理转发能力；不以这些能力作为项目验收条件。
- 客户端继续从 LiteLLM 或相应服务取得调用入口/Key；Relay 可读取权限允许的脱敏 Key 归属、用量/预算，但不要求读取或保存其完整秘密值。
- 运维监控使用管理员配置的既有只读/集成凭据，主动探针可使用既有专用调用凭据。输入监控凭据、设备配对与“给客户端发调用 Key”分别建模，不互相授权。
- 首期仍须交付 FR-W02 的六服务运维监控，不能因未实现 Key 管理而削减状态、告警、诊断或版本视图。新增 Key 管理以后另提范围，不默认进入当前工作包。

### 5.1 LiteLLM 数据库与日志接入路线（FR-D01/D-02/D-14；步骤以操作手册为准）

LiteLLM 数据库用于网关自身 Key（由网关管理）、请求消费记录及数据库模型管理；Relay 只按目标能力接入，不复制 Key/扣费权威。建议在现有 Compose 中增加独立 PostgreSQL 服务或复用已授权 PostgreSQL 实例，并为 LiteLLM 创建独立数据库与账号；Relay 后续使用独立 `relay` 数据库/账号。当前用户已确认可以配置数据库，但以下仍需按安装镜像版本验证。

无推理服务监控可先接入；以下日志与写管理是独立能力分支，不能把数据库、模型迁移或 Key 管理作为六服务监控的必要步骤：

| 阶段 | 目标与操作入口 | 明确边界 |
|---|---|---|
| 第一步：数据库与用量日志 | 按 [NAS_SETUP.md](NAS_SETUP.md) 合并 PostgreSQL、独立业务库/角色、环境与日志开关；正文关闭，核对新请求记录 | 保留现有模型文件、Master Key、网络和调用路径；不创建 Relay 库、不迁模型、不切换客户端 Key；未在 NAS 执行 |
| 独立分支：模型/路由管理 | 按 [DEPLOYMENT.md](DEPLOYMENT.md) 第 6 节验证数据库模型、路由支持、备份/迁移/回滚，再在授权范围切换 | `DATABASE_URL` 不使文件模型自动可写；文件和数据库避免重复路由；按 AC-29 核验。调用 Key 管理不再是必需交付 |

Master Key、Salt Key、数据库密码分别管理，恢复依赖必须保留且不写入文档。首次日志接通不自动启用 `STORE_MODEL_IN_DB`、正文或真实付费测试。详细配置参数和命令只在操作手册维护；本节定义需求前提与阶段边界，不是已执行记录。

### FR-K03：秘密存储（目标已确认；保护实现由 T-02 设计）

- LiteLLM 管理/集成 Key 仅存于 NAS 服务端；Mac 保存设备凭据，不保存网关管理 Key 或上游 Key。
- 新服务端秘密保护方案需独立设计：访问控制、存储保护、备份、轮换、丢失恢复与日志脱敏。
- 不将旧工程的 Keychain 决定自动套用到新 Mac/NAS；设备凭据和服务端凭据的具体存储方案待设计。
- 文件权限、环境变量或 Compose secrets 文件挂载不得描述成加密保险库。
- 不把管理 Key 无差别注入客户端容器。本项目无旧 Relay 数据导入前提；管理员在 NAS Web 受控配置上游/余额秘密，不能通过 Mac 缓存、普通导出或 iCloud 传递秘密。版本升级保留安全存储依赖，恢复缺失秘密需重新配置。

### FR-K04：管理权限分级（CONFIRMED，2026-10-07）

以下分级已获用户确认，是 Relay 自身的权限边界，不声称 LiteLLM 社区版提供等价的细粒度角色。实际只能使用高权限网关 Key 时，仍由 Relay 限制可调用操作并隔离该 Key。

| 级别 | 示例 | 约束 |
|---|---|---|
| 只读 | 模型/渠道目录、统计、脱敏日志、探针结果 | Mac/Android 默认只读；仅可更新自身已读/通知游标；含正文日志另行授权 |
| 日常管理 | Relay 连接/分组/检查计划、探针策略、通知静默、设备撤销 | NAS Web 管理员操作；显示目标、范围和结果并审计 |
| 高风险配置 | 上游凭据、模型新增/删除、路由/fallback、扩大探针费用、启用正文、清理历史 | NAS Web 二次确认和变更摘要；失败不制造伪成功 |
| 基础设施 | 容器重启/升级、数据库迁移、NAS 文件/持久卷操作 | 首期提供操作指引，不默认代执行或挂载 Docker socket |

- 确认权限方案不等于当前会话立即获准执行所有写操作；高风险动作按上述二次确认规则执行，NAS 部署/数据迁移仍需明确范围授权。
- Web 管理员账号登录；Mac 一次性配对码换取独立、可撤销设备凭据，Android 按 FR-C06 复用此机制。只读设备不能调用业务管理写 API，仅可更新自身已读/通知元数据，正文默认仅 Web 管理员查看；具体会话/配对有效期、密码保护和秘密存储在设计中落实。
- 若采用数据库管理模型，先规划现有文件模型的迁移、备份和回滚，不能直接重复导入造成双路由。
- 文件来源模型的管理受实际 API 限制：不能假装通过 API 已修改 `config.yaml`；此时提供配置指引或确认后的迁移方案。

### FR-K05：调用 Key 交付与轮换（移出当前必需范围；D-14）

原 Key 一次性交付、客户端配置导出、普通轮换和紧急撤销方案保留编号追溯，当前不要求实现，不设置相关操作入口。AC-42/43 在当前基线不适用；不能因无此功能阻塞运维监控验收。

服务监控凭据仍可由管理员在 Relay 单向输入/更新，按 FR-K01/K03 保护、不回显；其轮换由原服务负责，Relay 只更新接入引用。设备令牌的配对/撤销继续属于 Relay 自身身份管理。

## 6. 统计、日志与账本

### FR-D01：请求范围与统计（CONFIRMED）

- 读取网关已记录的请求、模型、Key 归属、Token、计算费用、时间及实际可得的状态/延迟。
- 支持按日/月、模型、Key、实例筛选；未支持维度明确标识，不用空值伪造支持。
- LiteLLM 统计仅覆盖经过该网关且实际被记录的调用，不代表整个 NAS 或全部供应商账单。
- 直连 Ollama、workbuddy2api、供应商的流量不自动计入。
- 区分用户调用、探针/评测调用及无法分类的调用；不能保证上游内部健康检查都带独立 Key，无法分类时不得冒充用户消费。

### FR-D02：价格与余额（CONFIRMED）

- 网关计算费用、上游已确认账单和上游账户余额分别展示，不叠加为“总消费”。
- 支持不同渠道价格、原生币种/积分、折扣及来源记录。
- 金额区分已确认、估算、未知；未知价格不能作为免费或 0 费用。
- Token 数量缺失与真实 0 分开；缓存/推理等分类仅在来源提供时展示。
- 汇率保留来源和有效时间；不可比较、过期或不完整时不进行误导性汇总。
- 余额/账单连接器属于独立能力，调用 Key 不保证能读取余额。
- 供应商余额展示为已确认首期需求，保留旧 Relay 的 Pipio/DeepSeek 等已有支持，按实际凭据和接口分别验证；采集移到 NAS，Mac 读取服务端快照。
- 同一家 Pipio 承载多个模型家族时按真实账户归属展示余额，不按 `xai_config`/`deepseek_config` 标签复制账户余额；不同账户即使同域名也不合并。
- 经 Pipio 调用 DeepSeek 模型不代表使用 DeepSeek 官方余额；只有配置官方账户并验证官方余额接口后才展示对应账户余额。workbuddy2api 可得额度/统计另标来源，不能冒充供应商现金余额。
- 模型调用与余额管理凭据用途分离；历史文档/源码可复用但不代替本次认证接口验证。缺失权限显示未知/待配置，失败保留旧快照和时间。
- 默认统计时区 Asia/Shanghai（北京时间）；金额保留原始币种/计量单位，人民币换算单独显示有效汇率和来源（CONFIRMED）。LiteLLM 计算费用、供应商实际账单、余额分别展示，不重复相加。

### FR-D03：采集一致性（PROPOSED 必要约束）

- 正确处理分页、窗口、时区、接口截断和保留期；展示数据覆盖范围与完整性。
- 以稳定请求标识或已验证的去重规则实现幂等采集，不只靠时间戳去重。
- 增量游标与对应数据需一致提交；失败不能推进游标而丢失记录。
- 请求、重试尝试和逻辑调用需区分；准确呈现无法确认的计数口径。
- 可重叠回查处理延迟入库；源日志缺失时不能声称恢复出完整历史。
- 服务端为统计事实源，Mac/Android 仅缓存；禁止 NAS、客户端与 iCloud 并行写同一账本。

### FR-D04：隐私、保存与查看（可配置和默认策略 CONFIRMED）

- 用户接受前次建议默认：请求元数据 180 天、日/月聚合 2 年；正文默认关闭，显式开启后保留 7 天。保存开关和期限可配置，由 NAS Web 管理。
- 各数据分类明确展示“是否保存、默认/当前保留期、实际已采集字段、覆盖时间、是否包含正文、缺失原因”；可以查看设置和已保存记录，不能把开启开关等同于已采集成功。
- 请求元数据包含来源可得的时间、模型/部署、Key 脱敏归属、Token、费用来源、状态和延迟；秘密值、Cookie、订阅会话始终不得进入日志。
- 开启正文后支持保存/查看实际采集到的请求提示词和回答；工具内容、附件等额外范围单独说明，不自动全部包含。源接口没有正文时标记未采集/不支持，需设计独立日志接入，不能承诺单靠统计接口获得正文。
- Web 管理员可查看日志/保存配置及按权限查看正文；Mac 默认展示监控摘要、趋势、告警和脱敏详情，不批量持久化正文，也不借正文查看权限获得管理写权限。
- Web 留存全部告警（CONFIRMED）：默认不自动过期，不仅保留未读或当前异常；已读/恢复事件仍可查询。磁盘风险需提示，后续缩短告警保留期或清理属于显式高风险操作。
- 探针结果与合成测试证据默认保存 90 天，可配置（CONFIRMED）；不与普通用户正文混为一类。告警仍全部留存，证据过期后保留告警但明确标记证据已过期。
- 各数据源（LiteLLM、Relay、直连适配器）分别标明实际采集/保存状态；一个脱敏开关不能代表全链路已安全。
- 原始日志、正文和聚合保留独立，关闭采集默认只停止新增、不隐式删除历史；缩短期限或清理先预览影响并确认。正文过期后不得通过引用或 Mac 缓存继续获取原文。
- 汇总必须标明统计覆盖；删除原始数据后的聚合不能伪装仍可展开原始明细。导出/备份默认不含秘密或正文，包含正文需明确授权。
- 时区和金额口径已确认，见 FR-D02；无有效汇率时不展示伪造人民币合计。
- 启用日志后的新请求可采集；没保存的旧请求不能恢复，Ollama 直连等数据缺口不伪造为零。

### 6.5 数据细则（D-05/06 默认目标已确认；D-04 范围待确认，技术实现 T-03）

- 正文首期建议限定为实际采集到的文本提示词/文本回答；工具参数/结果、图像、音频、视频、文件、系统提示词及流式中断的部分内容是否保存需逐项选择，不通过“保存正文”自动扩大授权。脱敏元数据仍受 FR-D04 约束。
- 即使正文开启，也只采集明确选定的数据源/范围；页面说明成功、失败、取消和部分输出各能得到哪些字段。不能将修改 Open WebUI/Hermes 调用路径作为无须确认的前提。
- 日/月边界按已确认 Asia/Shanghai 计算；真实零值、未采集、权限不足、估算、过期快照分别展示，来源时间与采集时间分开。消费、账单和余额不混为同一数值。
- 建议价格记录来源、币种/单位、生效时间与人工覆盖；人民币换算为辅助估值，不改写原始金额。D-06 已接受首期手动汇率、注明来源/生效时间、超过 7 天不作当前换算；自动接入仍为后续评估。
- 统计/余额/目录/告警的刷新目标与超时后过期阈值应分别展示并可验证，不能将 60 秒网关健康检查周期当成所有数据刷新周期，见 D-05。
- 备份、迁移快照、导出和在线数据有不同生命周期；在线正文到期不自动证明备份副本已清除。含正文备份的权限、保留期、恢复后清理与删除承诺须明确告知并确认，见 D-10。

### FR-D05：正文接入与采集失败边界（PROPOSED；D-04/10、T-03）

- 正文接入方案需验证成功/失败/取消/流式中断可获得的字段、来源与交付语义；不得把开关开启或回调触发等同于完整落库。
- 建议日志采集失败不阻断既有推理，显示采集缺口、最后成功时间和是否可回补；若用户要求正文不能丢失，需另确认可恢复缓冲、容量和运维责任，不默认承诺无损投递。
- 开关包含策略版本与生效边界；关闭后拒绝继续新增不符合策略的正文。已入队正文如何停止/清理与在途回调如何处理需说明，不能仅关闭页面显示。
- LiteLLM 源端日志、Relay 副本和备份分别说明保留/删除责任；源端未关闭时不得声称全链路停止保存。正文进入 Relay 时已超期则不发布，恢复备份后同样按原到期时间执行。

### FR-D06：指标口径与历史可比性（PROPOSED；D-05/06、T-03）

- 每个现有请求数、Token、费用、状态和延迟字段说明定义、来源、覆盖及缺失值；逻辑请求数与重试尝试数分开，来源无法关联时明确统计限制。
- 建议按源端请求开始时间转换到 Asia/Shanghai 归属日/月；缺失时注明替代口径。跨日结束不重复分配同一请求，不按每次采集时间重算历史所属日。
- 完整响应耗时与首 Token 时间分别展示；无首 Token 数据不估造。成功、失败、取消、流式中断和未完成各有明确状态，已发生费用仍保留，取消不代表免费。
- 模型/实例更名或停用不改历史稳定归属；历史显示当时名称和当前关联，避免按新名称重复统计。评测比较展示样本、版本及覆盖差异。
- 新增成功率/P95 等指标需要另定分母、窗口与样本数；本条先完善已要求的字段，不隐含新增指标承诺。

## 7. 探针与质量评测

### FR-P01：三种状态独立展示（CONFIRMED）

1. 可用性：认证、模型访问、请求/流式完成、超时、限流、延迟。
2. 能力：流式、工具调用、结构化输出、视觉、上下文及关键参数。
3. 质量：固定任务上的表现与基线变化。

状态包含通过、失败、不支持、未测试、过期和证据不足。网关进程正常不等于模型可用；请求成功不等于能力或质量合格。

### FR-P02：基础探针复用（CONFIRMED）

- 优先读取既有 LiteLLM 健康结果，区分网关就绪和实际模型调用。
- 页面刷新不触发全模型主动推理。
- 缓存结果必须带检测时间和过期状态，不能无限显示绿色。
- 没有配置主动探针时不自动启用付费请求。

### FR-P03：主动能力与质量探针（CONFIRMED 目标，具体工具 PROPOSED）

- 测试集、提示词、参数、评分规则及基线版本化。
- 固定实际部署；禁用会掩盖目标失败的 fallback。无法固定时只能报告路由组结果，不能声称验证了具体渠道。
- 控制输出预算、推理参数、缓存及采样，重复检测后判断趋势。
- 优先客观断言、结构验证和受控单元测试；模型裁判作为补充并标注其局限。
- 排除超时、截断、预算不足、参数被移除、路由变化造成的误判。
- 可比较经网关与直接上游结果，但直接验证需要另行授权上游凭据和费用。
- “疑似质量回退”附样本量、版本、失败示例和对比基线，不证明模型身份。
- 使用合成测试数据；若执行模型生成代码，必须隔离网络、文件、秘密和资源，不在 NAS 宿主机直接执行。

### FR-P04：范围、费用与资源控制（覆盖、默认值与保护规则 CONFIRMED）

- 可用性探针覆盖本轮启用且可安全测试的配置具体模型/部署，默认每 30 分钟；Ollama 等暂缓对象不调用，Agent 路由先核实安全。能力/质量默认周期均为每 24 小时，不要求全量，分别可改指定模型或 Top 5；周期/费用可改，按模式选择测试。
- 可用性检查将所有配置具体模型纳入待测清单；能力/质量仅将各自选定范围纳入对应计划。预算不足时不强行按期测完，分别展示未选入、未测、预算暂停、不支持、权限不足和覆盖率；不因未选入能力/质量测试就判断模型异常。
- 通配路由需先得到具体型号，不声称枚举了整个市场。新增具体模型可纳入已启用的可用性计划；能力/质量按各自指定范围或 Top 5 规则选择，不自动全量扩大。所有新增任务仍受授权范围、预算和适用测试类型限制，不自动扩大总预算。
- 能力与质量可使用不同模型名单，Web 展示选取模式、当轮入选模型及依据；Top 5 仅使用已采集的真实用户调用数据，排除探针/评测流量，不能因模型受测更多就反过来进入 Top 5。
- 默认使用最近 7 天真实用户逻辑请求次数 Top 5（CONFIRMED），排除探针/评测流量；不足 5 个仅选实际使用对象，没有使用数据时提示手动选择，不偷偷退回全量付费测试。能力/质量可分别改为指定模型。
- 排名按模型统计，入选后各已配置渠道/部署分别测试、分别报告（CONFIRMED）；用稳定部署标识识别，不能仅凭类似名称将 `cn:` 别名与另一渠道型号自动合并。真实同模型映射由目录或管理员确认，去重/并列规则由设计明确。
- 当轮冻结统计窗口和入选列表，说明统计覆盖、不完整日志/未知用户归属；缺少请求级证据的余额/日聚合不能据此构造完整 Top 5。未测/过期模型不显示为通过，新入选模型缺少同版本基线时先建立基线。
- 费用上限用于探针及质量评测的真实上游调用（包含重试及模型裁判），不是用户普通调用预算，也不是 Relay 收取的服务费。

- 未配置/未启用主动探针时不调用付费模型；本次确认策略不等于立即授权开发阶段真实付费测试。

### FR-P05：主动探针手动暂停与恢复（CONFIRMED 2026-10-09；执行细节 T-04）

- Web 管理员可暂停全局、指定实例或指定计划的主动测试；状态持久化，重启后继续有效。全局/实例/计划任一暂停限制生效时，手动测试也被拒绝，不能绕过预算或暂停。
- 暂停停止启动新的付费请求；提交暂停与任务启动之间需服务端原子校验。此前已获执行许可或已发送上游的请求列为在途，不保证取消成功或零费用；未知结果保留费用责任并继续对账。
- 主动探针暂停本身不停止请求元数据采集、余额读取、既有用户推理或原始告警留存；“暂停监控”的扩大影响见 FR-M03，不能用一个含糊开关合并。
- 恢复前预览适用范围、剩余预算、覆盖和将启动的任务；不集中补跑所有错过轮次，不自动提升预算。其他层级仍暂停时，仅解除一个计划不代表已恢复运行。

### FR-P06：多实例预算、调度公平性与基线有效性（原则 CONFIRMED 2026-10-09；配额/阈值细则 T-04/05）

- 日预算及并发限制按整个 Relay 合计，不为每个接入实例自动复制一份 1 USD/日预算；Top 5 显式记录选定实例集合与统计覆盖。实例内配额不增加总预算，具体默认集合/份额由 T-04 给出并验证。
- 可用性、能力与质量共同受总额约束；建议按费用预览配置轮转份额/配额，避免可用性永远占满导致质量任务饥饿，不擅定百分比。所需最小有效轮次超出预算时显示不可完成与预期覆盖，不把零散样本当完整测试。
- 每轮冻结实例集合、统计窗口、稳定模型映射及部署清单；任务去重、费用预留和执行许可需覆盖自动/手动测试。预算对未知结果保守记账，跨日和恢复备份不自动释放可能已消耗的费用。
- 质量基线启用需保留确认依据，并与部署、测试集、评分、参数和样本关联。任一关键维度变化或依赖证据到期（默认 90 天）后，不继续给当前质量回退结论；明确不可比较/待重建。
- 上游版本未知时说明比较局限，不声称证明模型身份。新建基线仍受预算/授权约束；失败/不完整轮次不自动替换有效基线。历史告警保留但证据有效性单独显示。

## 8. 告警与状态

### FR-A01：告警而非自动处置（首期通知范围 CONFIRMED，判断阈值 PROPOSED）

- 支持持续不可用、认证失效、日志采集失败、预算接近阈值、疑似质量回退和恢复事件。
- 质量异常仅告警，不自动全局封禁、修改路由或切换模型。
- 首期通知范围已确认：Web 留存全部告警；Mac 在线、授权有效且系统允许通知时发送本机通知；本机设置可关闭通知，但不影响 NAS 记录。
- Mac 离线时 NAS 继续保存事件，重连后可查看漏看的告警；不保证离线实时通知。是否将积压事件合并通知在设计中确定，不逐条轰炸。
- 邮件 SMTP、Webhook 等外部通知不属于首期；先前外部渠道建议已由用户本次选择收敛。
- 告警附实例、部署/模型、原因、检测时间和脱敏证据；不附 Key 或完整用户内容。
- 有防抖、去重、冷却、已读/恢复状态，避免告警风暴；证据正文有自己的保留期，不能因告警长久保存而无限保留用户正文。
- Android 按 FR-C06/D-13 复用同一告警事实、静默/去重与每设备已读规则；通知许可/后台限制分别验证，不把 Mac 在线本机通知或前台轮询能力当 Android 后台即时送达承诺。

建议判断规则（仍为 PROPOSED；本次通知选择不等于确认全部质量阈值）：

- 可用性：连续 3 次有效失败告警；超时、认证、限流和网络故障分别归因，恢复连续 2 次成功后通知。
- 能力：验证实际结构和工具参数，不以 HTTP 200 判定通过；仅对该模型声明/基线中具备的能力检查回退。
- 质量：同一部署、测试集/基线版本与参数，优先客观断言；建议至少 10 个适用用例、每例重复 3 次，形成有限样本结果。
- 通过率相对基线下降 20 个百分点，且连续两轮出现时产生“疑似质量回退”；同时展示样本数和不确定性，不把该启发式阈值称为统计显著性或模型鉴真。
- 先排除截断、参数丢弃、预算、超时、缓存、路由变化；模型升级需新基线，不把新旧版本直接当同条件比较。
- 参考 Uptime Kuma 的重试/通知机制及 Promptfoo 的断言、阈值、重复评测；不将上述参考理解为已批准引入依赖或通用“降智标准”。

### FR-A02：维护通知静默（CONFIRMED 2026-10-09；执行细节 T-06）

- Web 管理员可设置有范围、到期时间和原因的通知静默，支持手动提前解除；范围需明确为全局或实例/告警规则，不能无意静默其他实例。
- 检测及告警事件继续记录，静默仅控制在线 Mac 弹窗/通知分发，不改变原始健康状态、已读状态或费用；Web 仍可查看。需要停止付费测试时另用 FR-P05。
- 到期或解除后合并提示仍活跃异常，不逐条补发静默期间全部历史；已有通知与去重/冷却规则继续生效。离线 Mac 重连按当前静默状态处理，不依靠本机旧缓存决定。
- 不扩展为自动维护、重启容器或自动更改路由。

### FR-A03：账户低余额提醒（首期 CONFIRMED；2026-10-09）

- 按真实账户原币/额度单位配置低余额阈值与恢复条件，使用已有 Web 留存及在线 Mac 通知路径，不引入邮件/Webhook。
- Web 配置流程：选择已验证余额账户 → 确认原币/额度单位 → 输入提醒阈值与高于提醒阈值的恢复阈值 → 选择启用 → 预览规则。恢复阈值用于防抖，未知/过期余额不执行阈值判断；无需为配置规则自动发起付费推理。
- 过期、未知、认证失败余额提示采集状态，不能判成低余额；共享账户在多个实例间只产生一个账户级事件。
- 此项不是 FR-A01 的探针预算接近阈值告警。Web 按账户设置开启/关闭、阈值和恢复条件；金额/积分单位不能混用，没有可读余额或未设阈值时提示待配置，不生成猜测告警。阈值数值由管理员在使用时配置，不要求在本轮统一指定。

## 9. Mac 客户端

### FR-C01：连接与自动重连（CONFIRMED）

- 首次配置服务地址并完成授权，保存设备连接信息。
- 重启、网络恢复后自动重连，采用退避、取消和错误隔离。
- 断线展示最后成功数据、更新时间和断线状态；不能冒充实时数据。
- 地址发现为可选功能；不自动信任新实例或发送原有凭据。
- 服务端不可达时不静默切回直接访问供应商，避免重复采集和凭据泄露。
- 默认设备只读、可撤销，一次性配对码方案已确认；证书信任/配对会话实现待设计。

### FR-C02：刷新一致性（CONFIRMED）

- 首页、账户/网关详情、模型详情随同一数据版本更新，详情页不保留打开时的静态副本。
- 临时读取失败保留旧数据与窗口，并显示失败信息；仅确认删除后展示删除状态或退出。
- 隐藏列表项不等于删除，隐藏/停用对象的已打开详情仍可展示其保留状态。
- 跨日消费及时失效，不能把昨日值继续显示成今日消费。
- 单个网关或上游失败不覆盖其他正常数据。

### FR-C03：交付边界（系统/模式/更新控制 CONFIRMED；签名资源与构建待验证）

- 目标 macOS 27，不保留独立本地直连模式；NAS 不可达时只显示离线缓存。
- 需要自动检查/下载更新；安装/重启由用户选择窗口，本项目数据升级迁移期间不强制更新。正式分发采用签名/公证及更新包验证，具体发布资源/渠道需在交付前核实，不以关闭校验绕过。
- Mac 只包含连接/配对、展示/通知、本地偏好及更新设置；模型/路由、探针和数据保留管理放在 NAS Web；调用 Key 管理按 D-14 不列必需范围。
- 复用来源为 `https://github.com/DavisDing/Relay`；已有文档明确菜单栏、Popover、账户详情、设置等 UI 保护范围，保留原生视觉和通用导航，必要的连接/管理区域变化需说明，不以授权重构为由随意重设计。
- 新 Mac 客户端是本项目组成部分，仅支持 M 系列/Apple Silicon、macOS 27；采用站外安装与更新，不上 App Store、不交付 Intel 版本、不保留独立本地直连模式。首期不迁移旧 Relay 数据，但必须保证本项目后续 NAS/Mac 升级的数据兼容。
- 自动配置 CC Switch 等其他客户端不纳入当前默认范围，另行明确目标与授权。

### FR-C04：本项目初始化与版本升级兼容（CONFIRMED；2026-10-09）

- 本项目是新项目，首期默认没有旧 Relay 业务账本、旧 Relay 本地数据或旧 Relay 云同步数据；首装从空数据初始化，不把旧 `DavisDing/Relay` 工程作为首期运行数据迁移来源。
- Mac 客户端与 NAS Relay 服务端/Web 同属本项目交付边界；首期以版本化 API、数据库 schema、服务端快照和 Mac 本地缓存/设置为兼容对象。
- 每次 NAS/Mac 升级前记录应用版本、API/schema 版本和数据迁移版本；服务端按已验证备份/恢复方案执行 schema 迁移，Mac 先协商最低/最高支持 API 版本，再决定正常升级、只读兼容、要求升级或安全拒绝。
- 服务端保留必要的向后兼容窗口：未知字段可忽略、已废弃字段按版本转换；删除/重命名字段前先经过迁移和至少一个发布周期的兼容读取。不能把“客户端能连接”当作数据兼容已通过。
- Mac 本地只缓存可从 NAS 重建的快照、展示缓存、连接身份引用和用户偏好；缓存 schema 变化时优先清空并从 NAS 重建，不删除 NAS 事实数据。不可重建的本地设置必须有显式迁移器和回滚路径。
- 服务端升级失败、数据库迁移失败或版本不兼容时，保留原数据并进入只读/维护状态；不得通过降级镜像直接假设数据库可逆。升级前备份，升级后核对对象数量、关键金额、时间范围、任务/告警和权限关系。
- Mac 自动更新与 NAS API 兼容检查分离：坏签名、版本不兼容或迁移失败时保留可运行版本；不强制在数据迁移未完成时升级或清理缓存。
- 本项目未来版本若需要导入外部数据，另立版本化导入流程，不把它混同首期初始化；秘密、正文和备份仍按各自保留/恢复规则处理。

#### 运维页面与操作台范围（同属 FR-W02；运维能力）

7. **版本与更新**：展示 Relay 自身版本/API/schema 兼容状态，以及外部服务经 Web/API 可得的自报版本。运行容器 digest 只有在获得明确授权且无需文件/卷访问的只读 API 数据源时才显示；否则将运行版本标为未知，不用 registry 标签推断运行容器更新状态，并提供 UGOS/Compose 人工核对指引。容器 pull/recreate/restart/rollback 不由 Relay 执行，仍由用户在 UGOS/Compose 管理端操作。
8. **系统设置与审计**：管理 Relay 自身管理员/设备、只读连接凭据引用、检查频率、保留策略、时区/通知和功能开关；审计操作者、时间、目标、参数摘要、结果。不允许通过普通运维页面查看秘密原文。

- 项目提供 Web/API 监听入口和同源鉴权；本地访问及用户自行配置的 HTTPS 反代均不绕过管理员登录/设备配对。只验证项目自身 Cookie/会话、代理兼容与客户端证书校验，不接管 Lucky 证书/规则配置；网关管理端和数据库默认不对公网发布。
- 上游/探针地址需 SSRF 防护；Ollama 等私有端点只能经管理员明确许可，不全局关闭防护。
- 限制请求体、查询窗口、日志导出、任务并发和评测资源。
- 基于实际 NAS 测量内存、CPU、磁盘及并发，不承诺 N5105 能承担高并发质量评测。
- 首期避免不必要的 Redis、Prometheus、Grafana 等附加依赖；有明确收益再加入。

### FR-O03：受控恢复、权限失效与单活（原则 CONFIRMED 2026-10-09；实现 T-02/07）

- 恢复入口先确认管理员身份、隔离原运行实例，恢复副本默认进入主动探针及网关管理写入暂停状态；只读核对允许按实际环境开展。说明所恢复的库/文件、时间点、版本与秘密依赖。
- 受控恢复后旧 Web 会话、配对码、Mac/Android 设备凭据及临时操作授权失效，经管理员重新授权；不能依靠旧备份里的撤销记录证明安全。管理员密码泄露时需另走重置/轮换，不能只更换设备凭据。
- 只恢复 Relay 库不覆盖 LiteLLM 当前 Key/路由；恢复 LiteLLM 库时单独核对已撤销调用 Key 是否复活及预算/路由变化。两库恢复顺序与一致性点在运维指引说明。
- 对账当前网关、采集游标、执行中任务和当日费用；不重放已执行任务，不因旧预算快照再次发放完整当日额度。费用无法核实时保持付费暂停，明确人工核对入口。
- 只允许一个执行主体主动采集/付费调度；同库可用租约控制，但独立复制库不共享租约，需部署/恢复流程确保单活。首期不承诺自动识别任意人工克隆或跨 NAS 自动容灾。
- 备份正文按原到期时间过滤；秘密不在备份中时明确重新配置步骤。建议数据丢失/恢复目标按 D-10 冻结并实测，手动备份指引不等于已实现自动备份频率。

### FR-O04：脱敏诊断摘要（首期 CONFIRMED；2026-10-09）

- 可复制 Relay/网关版本、支持矩阵、最近采集/任务状态、错误分类和追踪 ID；默认不含正文、秘密、完整内部 URL 或个人标识。
- 管理员导出前预览；不自动上传第三方。完整诊断包、业务 CSV 报表另行确认，不能从“诊断摘要”推导已支持全部报表。
- 首期交付复制/导出前预览的脱敏摘要，与 D-04/10 对齐隐私和运维边界；完整诊断包、自动上传与业务 CSV 报表不在本次确认范围。

### 10.1 首期横向行为补充（PROPOSED；不增加公开运营或企业权限范围）

- 身份生命周期：首次管理员初始化不暴露公共抢注入口；密码重置、会话失效、配对码过期/重复兑换、设备撤销与凭据泄露后的恢复需在设计中给出安全流程。用户/管理员数量及设备可见范围由 D-01 确认。
- 管理可靠性：双击、重复提交、网关响应丢失、并发编辑和部分失败须有确定结果或待核对状态；高风险配置保留脱敏变更摘要和审计，不以无限重试替代结果核验。
- 采集和调度恢复：NAS 重启后恢复游标、任务状态和预算；错过的付费任务建议不集中补跑，避免成本/告警风暴（T-04）。过期状态与网络不可达分别展示。
- Mac 离线通知：建议重连后合并提示仍活跃异常和未读摘要，不将全部历史事件逐条发送；服务器继续完整留存事件（T-06）。配对撤销后不得继续读取新数据，旧缓存处理需明确。
- 空间与恢复：分别监测数据库、正文、证据、告警和备份占用；空间不足先报告受影响的写入/采集能力，不擅自删除永久告警或已确认保留的数据。备份职责和恢复目标见 D-10。
- 自动更新：有效升级失败不应破坏原可用安装；应用版本与 NAS API/schema 不兼容时显示阻塞原因，不强行迁移或静默回退直连。更新下载、安装、重启的用户控制方式见 D-09。

### 12.2.1 六服务运维监控的验收细化（AC-57/60；PROPOSED）

以下细化 D-12/D-14 的既有监控目标，不新增调用 Key、容器写管理或模型测试范围。六服务分别记录经验证的基础检查方法/地址、所需认证/权限、能力层级、时间和正常/失败结果；有可靠来源时记录安装版本，无法读取时明确标为未知/未验证。Relay 自身健康另按同一证据原则验证。模拟接口只能证明合同/异常处理，实际接入须另有 NAS 记录。

| 场景 | 预期与通过边界 |
|---|---|
| 正常与重启 | 每个已接入服务有经验证的无推理检查、当前结果/时间/耗时、历史与原 UI 入口（适用时）；重启后连接配置/历史保留，采集按计划恢复，不集中补跑旧检查 |
| 无 Key 管理、无网关 DB/探针 | 只配置 Relay 自身数据库及既有监控凭据；关闭调用 Key 管理、模型写管理与主动探针，LiteLLM 无数据库或不可达时，其余服务检查、历史、故障事件与只读端展示仍工作 |
| 单服务异常与恢复 | 注入超时、连接拒绝、认证失败、错误响应；只影响该服务及对应能力。故障/恢复按规则去重留存；目录成功或探针旧结果不清除另一层故障，未检查不当作健康 |
| 缺接口、旧数据与权限 | 支持矩阵区分无 API/无权限/未验证；可选日志、额度、运行 digest 缺失如实显示。失败保留最近成功值并标失败/时效；旧缓存、登录页 HTML 或全未接入不能冒充通过 |
| 暂停、手动刷新与静默 | 手动和定时检查共用限流/去重且不触发推理；暂停/移除后不发新检查，静默仍留存事件。配置改动前启动的旧结果不可覆盖当前状态；在途结果单独说明 |
| 数据一致性与设备隔离 | 检查历史、当前状态与故障事件提交一致；服务端重启/重复响应不重复告警。Web/Mac/Android 同一状态口径、每设备独立游标，撤销后拒绝读取；身份变化不发送旧令牌 |
| Relay/数据库故障 | Relay 整体失联时设备显示失联与最后成功同步时间；自身数据库不可用时不宣称历史/事件已落盘，不依赖已停止的 Relay 发送自身失联通知；恢复先核对状态，不重复执行付费任务 |

正常、异常和边界均需对应证据。目标服务完全无安全检查路径时保持阻塞；有能力限制但符合当前需求的可选数据明确不适用理由，不能自行把必需能力降为可选。

### 13.2.2 D-04：正文范围、接入与失败策略说明（待确认）

**元数据与正文分开**：元数据是时间、模型/Key 脱敏归属、Token、费用、状态等；正文是用户文本输入和模型回答。已确认“正文默认关闭、启用后默认 7 天”不代表所有消息/附件都获准保存。

| 内容类别 | 说明 | 推荐默认边界（未批准） |
|---|---|---|
| 用户文本提示/助手文本回答 | 普通聊天文本；可能含个人信息或业务秘密 | 仅明确选择数据源/Key/模型后采集；Web 管理员查看，Mac 不批量缓存 |
| 系统/开发者提示词、完整历史上下文 | 可能含应用内部规则和大量历史输入，工具回调常可看见 | 首期不默认保存；否则“仅当前问题”也可能误收整段上下文 |
| 工具参数/结果 | 文件路径、命令、数据库结果等，泄露风险较高 | 与普通正文独立选项，初期关闭；不能因 tools 能力探针开启而采集真实工具内容 |
| 图像/音频/视频/文件与 URL | 涉及二进制体积、外链权限、敏感内容和额外存储 | 不默认保存原附件；必要元数据脱敏，外链不能成为绕过原保留期的正文入口 |
| 失败/取消/流式中断 | 可能只有输入或部分输出，部分请求已收费 | 有字段才保存，标完整/部分/未采集；不存在的回答不补造 |
| Key、Cookie、认证头/会话 | 不是允许保存的正文 | 永不进入普通日志/正文/导出，先过滤再落库 |

**接入路线建议**：客户端继续直接 LiteLLM，Relay 读取请求元数据；正文优先从安装版本支持的日志扩展/回调采集，并在来源端按策略筛选。数据库启用不证明全部正文都可用；现成 HTTP 日志推送的许可与自定义回调实现须逐项核实。不默认把所有推理改走 Relay，也不直接读取 LiteLLM 私有数据库表来绕过权限。

**失败策略的取舍**：
- 推荐“推理优先”：Relay/日志入口断开时既有推理继续，正文可能有明确可见的缺口；恢复后只回补来源实际留存的内容，不承诺恢复未记录的回答。
- 若要求“不能丢正文”：需源端持久缓冲、事件去重、加密/磁盘/TTL、队列空间监控和恢复流程；即便如此仍需明确磁盘满时丢弃还是阻断，不可同时保证任意故障下永不丢失且推理永不受影响。
- 关闭正文后停止新增，队列和在途事件按生效版本处理；原数据按原 TTL 到期，不把关闭视为删除所有历史/源端/备份。源端保存与备份删除责任单独说明。

**D-04 需要确认的选择**：是否仅保存显式选定范围的用户文本输入/助手文本输出、排除系统提示/工具/附件；是否采用日志扩展而不改变客户端调用路径；是否接受采集失败时推理继续、正文缺口可见。当前仍 NEEDS_CONFIRMATION。
